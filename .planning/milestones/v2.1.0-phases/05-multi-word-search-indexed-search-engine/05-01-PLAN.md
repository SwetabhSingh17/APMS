### Root Cause Analysis
1. Across all client pages (`projects.tsx`, `student-topics.tsx`, `manage-project.tsx`, `team-management.tsx`, `user-management.tsx`, `supervisor-management.tsx`, `track-progress.tsx`), filtering is implemented as:
   `const q = searchQuery.toLowerCase();` (sometimes without trim)
   followed by:
   `fieldA.includes(q) || fieldB.includes(q) || ...`
2. When a user enters two words separated by a space (e.g. "Mohd Anas"):
   - `firstName` ("Mohd") does not contain "mohd anas".
   - `lastName` ("Anas") does not contain "mohd anas".
   - Neither single field matches the full query string containing the space, so all results disappear immediately.
3. When a user presses space after typing the first word (e.g. "Mohd "), without whitespace tokenization, `"mohd".includes("mohd ")` fails, giving the perception that spaces break the search.
4. Cross-attribute search (e.g., student name + enrollment number, or topic title + technology stack) is impossible under single-field substring matching.

### Solution Architecture (`client/src/lib/search-index.ts`)
1. **Tokenization (`tokenizeSearchQuery`)**:
   - Trims and lowercases input.
   - Splits on whitespace `/\s+/`.
   - Filters out empty tokens.
   - Normalizes diacritics / special characters where applicable.
2. **Consolidated Search Document (`createSearchDocument`)**:
   - Flattens all searchable attributes (strings, numbers, nested objects, array members) into a single unified lowercase text document.
   - Automatically handles name concatenation (`firstName + " " + lastName`, `prefix + " " + firstName + " " + lastName`).
3. **Multi-Token Match Engine (`matchesSearchQuery`)**:
   - Returns `true` if search query is empty.
   - Verifies that **EVERY** query token is present in the entity's search document (AND condition across tokens).
   - Allows tokens to match anywhere in the entity, across different fields.
4. **Index-Behaving Cache (`createSearchIndex`)**:
   - For collections (e.g. 700+ users, 150+ teams), pre-computes normalized documents and token sets once or on list change.
   - Provides instant $O(\text{tokens})$ lookup per keystroke with sub-millisecond execution.
5. **Server-side Search Tokenization (`server/db-storage.ts`)**:
   - Update `searchProjects` in `server/db-storage.ts` so `criteria.studentName`, `criteria.projectName`, etc., tokenize multi-word terms instead of doing single exact substring checks.
