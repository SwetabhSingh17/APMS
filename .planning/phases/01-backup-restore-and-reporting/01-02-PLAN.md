### Root Cause Analysis of Import Flaws
1. **Foreign Key Dependency Inversion:** In the current `importData()` implementation (`server/db-storage.ts` lines 1722-1776):
   - Users are inserted first (lines 1722-1732).
   - `users.group_id` references `student_groups.id`.
   - Any student with an assigned team (`groupId !== null`) fails the foreign key check and is caught by `catch (err)` and silently dropped!
   - Groups are inserted afterwards (lines 1734-1744).
2. **Missing Tables:** `projectAssessments`, `projectMilestones`, and `notifications` are never restored.
3. **Lack of Transactional Atomicity:** Previous inserts were done iteratively across unlinked try/catch blocks; if table 3 fails, the database is left in a corrupted half-restored state.
4. **No Safety Net:** If an admin mistakenly uploads an invalid file, the prior database state was already wiped with no rollback.

### Solution Design
1. **Automated Pre-Restore Safety Snapshot (`createPreRestoreSnapshot`):**
   - Before any truncate or data modification, execute `exportData()` and persist it to `database/backups/pre_restore_snapshot_[TIMESTAMP].json`.
   - Only proceed with restore once the safety snapshot is verified on disk.
2. **Topological Dependency Order Insertion:**
   - Step 1: `student_groups` (no outward FK dependencies on other data tables).
   - Step 2: `users` (now safely resolves `users.groupId -> student_groups.id`). Skip re-inserting the active admin or update with care while preserving session.
   - Step 3: `student_group_members` (resolves `users.id` & `student_groups.id`).
   - Step 4: `project_topics` (resolves `submittedById -> users.id`).
   - Step 5: `student_projects` (resolves `studentId -> users.id`, `topicId -> project_topics.id`).
   - Step 6: `project_assessments` (resolves `projectId -> student_projects.id`, `supervisorId -> users.id`).
   - Step 7: `project_milestones` (resolves `projectId -> student_projects.id`).
   - Step 8: `notifications` (resolves `userId -> users.id`).
3. **Atomic Transaction Wrapper:**
   - Execute all truncate and insert operations within a single `db.transaction(async (tx) => { ... })`.
   - If an error occurs at any step, the transaction rolls back cleanly, leaving the existing database completely intact.
4. **Sequence Realignment (`syncSequences`):**
   - After successful import, iterate over all 8 tables and invoke `setval(pg_get_serial_sequence(table, 'id'), MAX(id) + 1, false)`.
5. **Universal Payload Parser:**
   - Accept either parsed JSON object, JSON string, or multipart ZIP file buffer containing `manifest.json` and `portal_full_backup.json`.
